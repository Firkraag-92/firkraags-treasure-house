# 00 · 总览与规范

> 先核对基底、再确认红线，最后才动手 —— 这一层定义「怎么用这套知识库」。

## 这一层讲什么

这里是元规则层：一支 exe 能不能用本库的地址表、哪些改动绝对不许做、每篇文档要怎么写、还有什么没闭环。

任何一次动手之前，建议至少读完 `版本与基底` 与 `项目约束与安全红线` 两页 —— 它们决定了后面所有结论是否成立。

## 文档索引

| 文档 | 内容 | 什么时候读 |
|---|---|---|
| [版本与基底](版本与基底.md) | md5、文件长度、9 段段表、入口 RVA、锚点字节；判断一支新 exe 能否复用地址表 | 拿到任何一支新 exe 的第一件事 |
| [项目约束与安全红线](项目约束与安全红线.md) | 硬要求：不改长度/段表/入口/IAT/数据表；允许与禁止的改动形态表；结构影响核对清单 | 写第一个字节之前 |
| [知识库规范](知识库规范.md) | 七章节骨架、证据等级、UTF-8 带 BOM、相对链接、目录 README 导航卡的角色 | 新建或重构页面时 |
| [知识条目模板](知识条目模板.md) | 可直接复制的空页面骨架，章节顺序固定 | 新建条目时 |

## 阅读顺序

- 第一次进本库：`版本与基底` → `项目约束与安全红线`。
- 要加页面：`知识库规范` → `知识条目模板`。
- 每次改完：在 `更新记录` 顶部加一行口径变化。
