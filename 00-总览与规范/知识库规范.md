# 知识库规范

## 结论速览

- 本页定义本知识库的写作、证据、编码与维护规则。
- 根入口固定为 `README.md`，主题文档按编号目录分层，不建平铺文件。
- 每篇文档必须保留七个固定章节，可按需追加「详细记录」「调用链」「字节证据」。
- Markdown 统一带 BOM 的 UTF-8；链接必须使用本库相对路径。

## 适用版本

- 默认：6.1 魔改引擎（罡星煞曜传）`Ekd500.exe` / `Ekd5.exe`。
- 其它引擎（6.5PL、6.6、瓦岗、原版）只进入 `09-版本与外部资料`，不得写成本库的默认写入路径。

## 已确认事实

- 本库以「本地反汇编 + 实机验证」为唯一写入依据；论坛资料、其它 MOD 经验只能作为线索。
- 一个主题一个主文档；重复内容合并，旧入口进 `90-来源归档`。
- 地址一律写成 `0x` 前缀十六进制；文件偏移与 VA 必须写清是哪一种。

## 实现/使用方法

每篇文档的固定骨架：

```markdown
# 标题

## 结论速览
## 适用版本
## 已确认事实
## 实现/使用方法
## 风险与边界
## 证据来源
## 待验证项

## 详细记录（可选）
```

写作要求：

1. 「结论速览」2–5 条，写清**能直接拿去做补丁的结论**，不写过程。
2. 「已确认事实」只写反汇编读过、或实机验过的东西；推断必须标「待证」。
3. 「实现/使用方法」写挂钩点、字节、洞穴、脚本、产物 md5。
4. 「证据来源」写原始文档相对路径与证据等级。
5. 「待验证项」写清缺什么验证才能升级为写入规则。

## 目录导航卡

- 每个编号目录（`00`–`10`、`90`）下放一个 `README.md` 作为导航卡：这一层讲什么、文档索引表（内容 + 什么时候读）、阅读顺序、上下游衔接。
- 导航卡**不受七章节约束**，但必须保证：索引表覆盖本目录全部主题页，链接用相对路径且可解析。
- 新增或改名主题页时，同步改本目录导航卡与根 `README.md` 的「分类总览」表。
## 风险与边界

- 不要把「同一函数在 6.5PL 里的地址」抄进 6.1 的条目 —— 两支引擎只共享 KOEI 底座。
- 不要把未闭环的东西写成结论（例如「SP 每关清空已完成」）。
- 不要复制大段原始反汇编进正文；只保留关键几行 + 原文路径。
