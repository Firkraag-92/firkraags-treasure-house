# 项目约束与安全红线

## 结论速览

- 用户对 6.1 exe 的硬要求：**不破坏原文件结构**，任何改动必须是「等长、最小字节、往空区放代码」。
- 绝对不动：文件长度、段表、入口点、导入表（IAT）、`ImageBase`，以及数据表本体（S 形象表 `0xD2800`、R 形象表 `0xE1000`、兵种相克 `0xA3280`）。
- 数据文件（`Data.e5`/`Imsg.e5`/`.eex`）**只在末尾追加**，不插中间、不改已有记录长度。
- 每次改完必须留下「修改日志 txt + 产物 md5 + 改动字节数 + 结构影响核对」。
- 需要实机验证时，当轮停下来一次说清步骤；不得在他打团/游戏时自动跑会抢前台与模拟键鼠的测试。

## 适用版本

- 6.1 魔改引擎（`Ekd500.exe` / `Ekd5.exe`）的全部补丁与数据改动。

## 已确认事实

- 用户明确拒绝「为了塞功能入口而移动游戏自带按钮」这类破坏手感的改法（套装面板入口必须自绘或放不扰动的角落）。
- 用户的 MOD 编辑器（`形象指定器w61.exe`、剧本编辑器）按**固定偏移**读 exe 与 Data.e5，任何布局变化都会让编辑器失效或报错。
- 改剧本 `.eex` 的长度即使 `eexlib` 自校验通过，编辑器仍可能打不开、游戏崩（已发生过一次，见 [失败与死路台账](../90-来源归档/失败与死路台账.md)）。

## 实现/使用方法

**允许的改动形态**

| 形态 | 说明 | 示例 |
|---|---|---|
| 等长字节替换 | 原指令与补丁字节数相同 | 改立即数（`cmp 0x400` → `0x800`） |
| 短跳转 + 洞穴 | 5–6 字节 `E9`/`E8` 跳到自己写在空区的代码 | `0x4784C7 → 0x639000` |
| 空槽填指针 | 引擎自带分派表里的空项写成自己的函数 | 72 子表槽 23 起 |
| 数据文件尾部追加 | 新增记录只加在文件末尾，旧记录偏移不动 | `Imsg.e5` 追加列传 |

**禁止**

- 扩大/缩小文件、改段表、搬入口、重写导入表。
- 在 `.rsrc`、对话框资源、数据表中间插字节。
- 为省事覆盖用户的编辑器写过的表（形象表、兵种相克、人物表）。

**每个产物的结构影响核对清单**

1. 文件长度 = 7,413,760 B？
2. 段表 9 段、VA/size/raw 未变？
3. 入口 RVA `0x817E0` 未变？
4. 导入表目录与 IAT 未变？
5. 差异字节是否全部落在「挂钩点 + 洞穴」？（给出 diff 字节数与命中区间）
6. 目标数据文件是否只追加、md5 记录？

## 风险与边界

- 「节可写可执行」不等于「每页可执行」：`0x629000` 页实测执行即崩。
- 洞穴的连续零区可能被别的补丁占用（`0x630000` 同时被张顺天运与清 SP 用过）。
- 强行改数据表布局（如 1024→2048 名册）会连带 SP 数组、变量表、Data.e5 全部后移 ⇒ 编辑器全废。用户已明确否决这条路。

## 证据来源

- 用户多轮明确要求（2026-10-19 ～ 2026-10-21），见 `112关工作目录\_exe分析\修改日志.txt` 与各案例文档。
- 证据等级：已验证（用户约束 + 实际事故）。

## 待验证项

- 形象指定器保存 exe 时是「原位改写」还是「整文件重写」尚未实测；建议改名后改一个形象、比 md5 验证（见 [形象表与形象指定器](../07-数据表与资源/形象表与形象指定器.md)）。
