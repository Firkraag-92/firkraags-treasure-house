# 72 指令分派体系

## 结论速览

- 剧本指令码 `72`（信息传送）走**两级表**：指令表 `0x410AD8` 的 `entry[72] = 0x47D89E`（分派器），分派器再按「子号」索引子表。
- 子表基址两引擎不同：**罡星 `0x47D903`**、6.5PL `0x47D8DF`（错开 `0x24`）。绝不能假设同址。
- 罡星子表 **槽 22..39 是 `90 90 90 90` 空槽** ⇒ 写一个函数地址进去，立刻获得一条新指令，零改 exe 主体。
- 处理器 ABI 统一为「一个文本缓冲区指针」参数，处理器自己用 `0x426E64` 解析后面的数字，尾部 `ret 4`。

## 适用版本

- 6.1 魔改（罡星 112/117 关基底）；6.5PL 只作对照。

## 已确认事实

**指令表**

- 基址 `0x410AD8`，index = 剧本指令码。
- `entry[72] = 0x47D89E`（旁证：`0x410BF8` 存着 dword `0x47D89E`，`(0x410BF8-0x410AD8)/4 = 72`）。

**分派器 `0x47D89E`**

```
push 4; ecx=[ebp+8]; call 0x4183F7   ; 取属性 4（子号）
cmp ax,0x8000; je fail
mov [ebp-4],ax
push 5; ... call 0x4183F7            ; 取属性 5（正文）
cmp eax,0x80000000; je fail
push eax; lea edx,[ebp-0x408]; push edx
mov ecx,0x492F90; call 0x4179A5      ; 转码到缓冲
lea edx,[ebp-0x408]; push edx
movzx eax,word[ebp-4]
call dword ptr [eax*4 + <子表>]
```

成功返回 1，失败返回 5。

**罡星子表 `0x47D903`**

| 槽 | 函数 | 用途（已核实部分） |
|---|---|---|
| 0 | `0x4081F2` | **改名**：变量 4054 的值当编号，`0x4D0C20` 读名字，写入 `0x510D00` |
| 1 | `0x40216C` | 未逐一核实 |
| 4 | `0x402AA6` | 未逐一核实 |
| 12–13 | `0x404F17`/`0x404E6C` | 与 6.5PL 同址，属底座 |
| 14–15 | `0x52D520`/`0x52D6B0` | 扩展段指令 |
| **16** | `0x4D4270` | **个人数据/扩展字段写入**（`72 16 编号 字段 值`） |
| **17** | `0x4D4380` | **部队数据写入** |
| 18–21 | `0x00000000` | 空 |
| 22–39 | `0x90909090` | **空槽（NOP）**，可直接填地址 |

**72/16 写入器 `0x4D4270`（ret 4）**

```
push 0 ×4
push 0x5E0000
loop i=0..2:
  push [ebp+8]; call 0x426E64       ; 依次解析：编号、字段、值
  inc edx; add [ebp+8],edx
  mov [ebp+i*4-0x10],eax
edx = byte[ebp-0xC]                  ; 字段号
if edx < 0xF:  mov word [0x5E0000 + 编号*0x40 + 字段*2], ax
elif 值 <= 0x78: mov byte [row + 字段 + 0x10], al
```

⇒ 字段 `<0xF` 写 **word** 到扩展行 `+字段*2`；字段 `≥0xF` 写 **byte** 到 `+字段+0x10`。由此得字段 16→`+0x20`、17→`+0x21`、18→`+0x22`、19→`+0x23`（异术/特技）、20→`+0x24`、21→`+0x25`，与「field 19 = 异术」的实测完全吻合。

**剧本写法**

```
72:信息传送 16 <人物编号>
19
<值>
```
编辑器显示为 `72 16 22 23 20` 这类一行三数（编号、字段、值）。

**解析器 `0x426E64`**

- 支持十进制、`-` 负数、`*N`（读变量表）、`vN`（`0x502000 + 4N`）。
- 返回 `eax` = 值，`edx` = 已消耗字符数；尾部 `ret 4` **自己弹掉参数**（这也是当年把它误判成「读指针低字节 bug」的原因）。

## 实现/使用方法

**给引擎加一条新指令（推荐路径）**

1. 选一个空槽（罡星 `22..39` 全是 `0x90909090`），子表地址 = `0x47D903 + 槽*4`。
2. 写 handler：入口只保证 `[esp+4]` 是文本指针（因 `ret 4`），内部用 `0x426E64` 逐个解析参数。
3. handler 尾部 `ret 4`。
4. 把 handler 地址写进子表槽。
5. 风险核对：确认该槽号在现有剧本里没被用过（`72/子号` 用量统计见案例页）。

**改现有指令行为**

- 优先改 handler 内部逻辑（写个洞穴 + 挂钩），而不是换 handler 地址 —— 换地址会同时影响所有调用点。

## 风险与边界

- 子表是 **dword 数组**，但空槽填的是 `0x90909090`，直接当指针会崩；判断「空槽」要按值比对。
- 6.5PL 的 `V23 = 0x408CFA`（设置列传重定向）在罡星表里不存在；罡星要自己写。
- 分派器先在 `0x4183F7` 里取属性 4/5，若剧本参数非法会返回 `0x8000`/`0x80000000`，handler 根本不会被调。
