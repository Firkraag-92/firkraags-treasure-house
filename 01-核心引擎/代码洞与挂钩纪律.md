# 代码洞与挂钩纪律

## 结论速览

- 洞穴一律选 `.data3` 里的**连续全零区**，写入前必须用脚本断言整段为 0；写完必须用 capstone 反汇编复核。
- 挂钩有三条铁律：①`call` 改 `jmp` 时自己 `push` 返回地址；②参数偏移整体减 4；③被改写区若有跳转落入，必须整块搬走或保留尾部。
- 汇编一律用 keystone，asm 源里**不能写 `;` 注释**（含连字符的注释会挂死）。
- 每个补丁脚本必须自带三层断言：基线 md5、原字节、洞穴全零。

## 适用版本

- 6.1 魔改 `Ekd500.exe`/`Ekd5.exe`。

## 已确认事实

**已知可用洞穴（全部位于 `.data3`，file = VA − `0x42E800`）**

| 区间 | 用途 | 状态 |
|---|---|---|
| `0x628000` 起 | 猛击（原版扩展代码，勿覆盖） | 引擎自带 |
| `0x62A000`–`0x62A600` | 盾反（原版扩展代码） | 引擎自带 |
| `0x62B000`–`0x62B100` | Z 超级加速（挂 `0x52F2D9`） | 已用 |
| `0x62B200`–`0x62B300` | 区域状变 v2/v3（HEAD/TAIL/PRES） | 已用，实测通过 |
| `0x62B400` (0x100) | 区域状变单位号缓冲 | 已用 |
| `0x62B500` / `0x62B504` | 区域状变 MODE / PTR | 已用 |
| `0x62C800`–`0x62C82B` | 装备适性白名单 | 已用 |
| `0x630000` 起 | 张顺天运（getter/说明/适性/名表）与清 SP 曾争用 | 已用，需重排 |
| `0x634000`–`0x634500` | 清 SP 帧门状态机 | 已用（功能未成） |
| `0x639000` 起 | 列传重定向 | 已用，实测通过 |
| `0x626000`–`0x84C000` | 约 2.2 MB 连续零区 | 可用 |

> `0x62D000` 在基线**不是全零**（断言失败过）；`.data3` 的连续零区实际从 `0x62F022` 起最稳。

**三条铁律（每条都踩过）**

1. **`call` → `jmp` 必须补返回地址**。原 `call X` 的下一地址是「挂钩地址 + 5」。洞穴末尾要 `push <返回地址>` 再 `jmp X`，否则 `X` 的 `ret` 弹出栈上垃圾，症状是「一进相关窗口/一攻击就闪退」。
   - 实例：`0x4784C7 call 0x40BFDB` → 洞穴 → `push 0x4784CC; jmp 0x40BFDB`。
2. **jmp 版参数偏移减 4**。call 版参数在 `[esp+4]/[esp+8]`，jmp 版在 `[esp]/[esp+4]`；`pushad` 后回写位置也同步变（`[esp+0x28]` → `[esp+0x24]`）。
3. **别只看挂钩点那几字节**。若附近有跳转落入被改写的区间，6 字节替换会把入口劈成两半（实例：`0x43F8B4` 只能改 6 字节，因为 `0x43F7E0` 有 `jmp 0x43F8BA` 直落其后）。

**keystone 的两个坑**

- `;` 注释行会报 `KS_ERR_ASM_MNEMONICFAIL`；`; ---- x ----` 会让 `Ks.asm` **无限挂死**。asm 源一律不写注释。
- 不要「分别汇编前缀再拼接」——相对跳转位移按各自地址算，拼接后全错位。（曾把 `call 0x436F28` 编成 `call 0x436F2D`。）

## 实现/使用方法

**补丁脚本骨架**

```python
BASE_MD5 = "6bd4c3ea68e7ad372a581718087ff36d"
assert md5(data) == BASE_MD5
assert data[off:off+len(orig)] == orig      # 原字节
assert data[cave_off:cave_off+size] == b"\x00"*size  # 洞穴全零
data[off:off+len(orig)] = new
data[cave_off:cave_off+len(code)] = code
assert len(data) == 7413760
```

**挂钩形态（最安全）**

- 5 字节 `E8 rel32`/`E9 rel32`：把原 5 字节换成 `E9 <cave>`。
- 6 字节：`E9 + 1×90`。
- 8 字节：`E9 + 3×90`（如 `0x43EA7B`）。
- 洞穴尾部还原原指令再跳回「挂钩地址 + 原长度」。

**写完必做**

1. capstone 反汇编洞穴，逐条确认（`chk_*.py` 模式）。
2. 统计 diff 字节数与命中区间，确认没有溢出到别处。
3. 本地冒烟：`Start-Process` + 重定向 stdout/stderr，5 秒存活；**不加重定向会把工具调用拖到超时**。
4. 实机验证清单写清楚，交给用户跑。

## 风险与边界

- 冒烟只能证明「启动不崩」，不能证明功能正确。
- 洞穴被两个补丁共用时（`0x630000`），合并必须先重排布局。
- 帧门（`0x42F7F0`/`0x42F7F4`）挂钩每次修改都要保留原指令 `movzx ecx,word[0x500F53]`。
