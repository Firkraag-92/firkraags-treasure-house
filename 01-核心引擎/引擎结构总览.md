# 引擎结构总览

## 结论速览

- 这支 exe 是「KOEI 底座 + 小白狐扩展」的叠加体：`.text` 里是底座与少量改写，真正的扩展逻辑大量放在 `.data2`（第二段 `0x526000` 起）与 `.data3`（`0x626000` 起）里，以可执行代码形式存在。
- 因此「在 `.text` 里找不到某个功能」是常态 —— 必须把 `.data2`/`.data3` 当代码段反汇编。
- `.data3` 有约 2.2 MB 连续全零（`0x626000` 段内的尾部），这就是所有补丁的洞穴来源。
- 三套地址体系必须分清：文件偏移、RVA、VA（VA = RVA + `0x400000`）。

## 适用版本

- 6.1 魔改 `Ekd500.exe`（112 关）/ `Ekd5.exe`（117 关），两者同构。

## 已确认事实

**段角色**

| 段 | 主要内容 | 备注 |
|---|---|---|
| `.text` `0x401000` | KOEI 底座：战斗、必杀、剧本解释器、UI 分派 | 大量函数被小白狐改写或跳转 |
| `.rdata` `0x486000` | 字符串常量、格式串、部分表 | GBK 串集中区 |
| `.data` `0x48B000` | 全局变量、指针、部分表 | 含 `0x4917B0` 特效对象等 |
| `.dll` `0x4BE000` | 导入表 (`0x4860D8` 起是 IAT 实际地址) / DLL 相关 | IAT 命名见函数速查 |
| `.data2` `0x4CE000` | 大数组：S 形象 `0x501000`、R 形象 `0x50F800`、名字覆盖 `0x510D00`、变量表 `0x502000`、SP `0x501C00` | 与编辑器强耦合 |
| `.nodata` `0x516000` | 运行期缓冲/BSS | `0x53F570` 等例程在相邻区 |
| `.data2` `0x526000` | **扩展代码**：天运 `0x52D000`、圣水 `0x52C600`、效框架 `0x55xxxx`、情报窗 `0x5C3B50` | 可执行，需用 `dis2.py` 反汇编 |
| `.data3` `0x626000` | **扩展代码 + 洞穴**：猛击 `0x628000`、盾反 `0x62A000`、扩展行 `0x5E0000` 在 `.data2` 段内；零区从 `0x62B000` 起 | 我们的注射区 |

**关键全局与入口**

- 单位记录基址 `[0x4CEA00]`；尾 `[0x4CEA04]`；末条 `[0x4CEA08]`。
- 战场对象基址 `0x4B2C50`（步长 `0x24`）。
- 特效对象 `0x4917B0`。
- 剧本指令表基址 `0x410AD8`；`entry[72] = 0x47D89E`（信息传送分派器）。
- 剧本变量表 `0x502000`（`vN` = `[0x502000 + 4N]`）。

## 实现/使用方法

**定位一个功能的标准动作**

1. 先用字符串/资源找「用户看得见的锚」（如控件号、格式串、名表），拿到引用点。
2. 顺着引用点向上找入口函数，确认是 KOEI 原函数还是小白狐新写的（看调用约定：`ret N` 与 `plain ret` 混用是扩展代码的特征）。
3. 若函数地址落在 `0x526000` 以上，用 `dis2.py`（capstone，支持任意段）反汇编，不要只扫 `.text`。
4. 找调用者时**不要只靠线性反汇编**（对齐噪声会漏），用字节级 `E8/E9 + rel32` 扫描（`zz_xref_bytes.py`）。

**反汇编工具的正确性**

- `dis_any.py` 对某些地址会静默无输出 ⇒ 改用 `dis2.py <exe> <VA> <条数>`。
- `md.disasm` 线性扫描遇坏字节会停止 ⇒ 必须从「能让 disasm 恰好覆盖目标地址的起点」开始，或直接扫字节。

## 风险与边界

- `.data2`/`.data3` 里既有代码也有数据；把数据当代码反汇编会得到垃圾指令，容易误判「函数不存在」。
- `.data`（`0x48B000`～`0x4BE000`）里有一批「代码副本」调用 `0x3D8xxx`（低于 ImageBase，不可执行）⇒ 那是**死数据/旧副本**，不是活代码。活代码在 `.data2`/`.data3`。
- 段属性可执行不代表页可执行：`0x629000` 页实测崩。
