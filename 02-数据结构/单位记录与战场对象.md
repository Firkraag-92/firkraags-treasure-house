# 单位记录与战场对象

## 结论速览

- 全局有**两套对象**：1024 条「单位记录」（`0x48` 步长，长期数据，存档随它走）与 115 个「战场对象」（`0x24` 步长，只在本场战斗存在）。
- 单位记录基址在 `[0x4CEA00]`（运行期分配，例 `0x0F591000`），由 `0x43A060` 初始化；总长 `1024 × 0x48 = 0x12000`。
- 取址统一用 `0x4061E4(编号)`（结果在 **ECX**）或 `0x40620F(编号)`（扩展行，也在 ECX）。
- 从指针反查编号用 `0x40BE7D(指针)` = `(ptr-[0x4CEA00])/0x48`，纯函数、`plain ret`。
- 战场对象只按「战场序号 0..114」索引，编号与序号不是一回事。

## 适用版本

- 6.1 魔改（罡星 112/117 关）。

## 已确认事实

**单位记录（`0x48` 字节）已确认字段**

| 偏移 | 含义 | 证据 |
|---|---|---|
| `+0x00` | dword 单位编号 | `0x45F670` = `mov eax,[ecx]` |
| `+0x02` | byte | 载入器 `0x409018` 写入 |
| `+0x03` | byte | **6.5PL 用作列传重定向**；罡星载入器**不写**⇒空闲 |
| `+0x04`/`+0x05` | byte ×2 | 载入器写入 |
| `+0x08` | 名字缓存（用于改名覆盖的名 8 字节起） | `0x4081F2` 里 `add ecx,8` 后 strcpy |
| `+0x0C` | byte 阵营（0 我军 / 2 敌军 / 3 友军…） | `0x418C90` = `byte[ecx+0xC]` |
| `+0x1E` | byte 状态位（麻痹/禁咒/混乱…） | 状态施加链，见案例「猛击盾反」 |
| `+0x21..+0x25` | 招式/秘术/合技/异术/… | 载入器写入，`0x43D4A0` 读 `+0x23..+0x25` |
| `+0x2B` | byte 兵种 id | `0x40BF10` 换算地形行号 |
| `+0x2C` | byte 等级 | `0x4D40D0` 算 SP 上限 |
| `+0x2D` | byte（经验相关） | `0x4073BC` 尾部判 `+0x2C==0x63` 后写 `0xFF` |
| `+0x36..+0x47` | 未使用 | 载入器不写，可作扩展字段 |

- 载入器 `0x409018` 只写 37 个字节：`+4,+5,+2,+0x2A,+0x11..+0x1A,+0x21..+0x25,+0x1B,+0x1C,+0x1F,+0x20,+0x2B..+0x35,+0x27,+0x28,+0x29`。
- 记录随存档整条保存 ⇒ 写进空闲字节的扩展数据能随档走。

**战场对象（`0x4B2C50 + 序号*0x24`）**

| 偏移 | 含义 |
|---|---|
| `+0x0C` | byte 阵营（与单位记录同语义） |
| `+0x10` | HP |
| `+0x1E` | byte 状态位串（`0x02` 麻痹、`0x04` 禁咒、`0x08` 混乱、`0x10` 中毒、`0x20` 怯力、`0x40` 无名） |

- 状态施加入口 `0x40336A`（`or al,[ecx+0x1E]`，先过 `0x65` 免疫判定）。
- 清位函数 `0x418DA0`（参数 = 掩码按位取反）。

**越界守卫**

- `0x406764`/`0x4068A1`：`cmp [ebp+8],0x400; jb ok; xor eax,eax; ret` ⇒ 编号 ≥1024 静默返回 0。
- `0x4061F9`（取战场对象）对序号做 `and ecx,0xff` ⇒ 同场**最多 256 个序号**。
- `0x45AE08` 的区域扫描把单位号收集进 byte 数组，条数上限 `0x74`（116）。

## 实现/使用方法

**拿记录 / 拿扩展行**

```asm
push 编号
call 0x4061E4        ; ret 4，记录指针在 ECX
```
```asm
push 编号
call 0x40620F        ; ret 4，扩展行指针在 ECX
```

**从指针反查编号**

```asm
push 单位指针
call 0x40BE7D        ; plain ret，返回值在 EAX
```
注意：它只能吃 `0x48` 步长的单位记录；喂 `0x24` 的战场对象会返回垃圾（「盾反分支 0 触发」就是这个坑）。

**遍历全场单位**

```asm
mov esi,[0x4CEA00]
mov ecx,0
loop: cmp dword [esi], ecx      ; 首 dword == 编号才是有效记录（避免读堆垃圾）
      jne skip
      cmp byte [esi+0xC], 2     ; 阵营
      ...
skip: add esi,0x48
      inc ecx
      cmp ecx,0x100
      jb loop
```

## 风险与边界

- `+0x03` 在罡星是空闲字节，但**不要**直接套 6.5PL 的用法而不改读取端 —— 罡星情报窗根本不读它。
- `+0x08` 的名字缓存只在改名后才有效；不要把它当唯一名字来源（要兜底查 `0x510D00` 与 Data.e5）。
- 战场序号上限 256、同场状态特效上限 116、名册上限 1024 —— 三层限制互不相干。
