# 伤害结算与装备特效

> 一句话：物理伤害在 0x43BC62 结算（唯一出口 0x43BF11），策略伤害在 0x40D200 结算（出口 0x40D255）；装备特效由 0x4CF398 统一查询，特效名表在 0x5265C0 + id×16；引擎**自带一张远程判定表 0x4D2138[兵科行]**，物理伤害里只有它命中的攻击才算「远程」。

## 1. 结论速览

- 物理伤害主函数 `0x43BC62`（ret 0xC，ECX=攻击方，[ebp+8]=受击方，[ebp+0xC]=命中标志，[ebp+0x10]=type）。★ECX 与 [ebp+8] 都是 **0x24 字节的战场对象**（0x4B2C50 + 序号×0x24），**不是 0x48 单位记录**（见 3.1.1）。5 个调用点：0x419AEC、0x438A2A、0x438CCA、0x440668、0x5B0812（后者即「最终伤害」0x5B0800 里那次）。
- 策略伤害主函数 `0x40D200`（ret 8，**[ebp+8]=攻击方、[ebp+0xC]=受击方**），唯一调用点 0x43C0D4（上层 [ebp-0x18]=攻击方、[ebp+8]=受击方）。
- 装备特效查询：`0x4CF398(ECX=单位, 4 个栈参数, ret 0x10)` → EAX=百分比（默认 0x64），ECX=1 表示拥有该特效。
- 特效名表 = **0x5265C0 + id×0x10**，每项 16 字节 GBK。
- 引擎**有**「这次攻击是不是远程」的判定：`0x43FF9A(ECX=攻击方记录)` = 兵科行 → 查字节表 **0x4D2138**，只有该表为 1 的兵科才算远程（见 3.5）。实机印证：特效 22「减轻远程损伤」对步兵/骑兵的攻击没反应。

## 2. 适用版本

罡星煞曜传 6.1（112 关与 117 关两套 Ekd5.exe 在这一段逐字节一致；117 基底 md5 49A50A0C45FE6C91C9779607868004F0）。

## 3. 已确认事实

### 3.1 物理伤害 0x43BC62

- 入口 `sub esp,0x3c; mov [ebp-0x2c],ecx` —— **攻击方（战场对象）永远存在 [ebp-0x2c]**。
- `movzx eax,byte[[ebp+8]+4]; cmp al,0xff` → 受击方槽为空（+4 = 空槽标记）就直接返回 0。编号不在这里取，而是由 `push [对象]` 交给 0x4061E4 换算（+0 = 单位编号 dword）。
- 特效 22 查询点 0x43BCB7（`push 0,1,0x1F,0x16`，ECX=攻击方）；特效 35 在 0x43BE5F（`push 0,1,0x59,0x23`）。两者都是 `damage = damage×eax/100`，再 `0x42A959` 保证至少 1 点。
- 尾部（**唯一出口**）：
  ```
  43bf03  push eax
  43bf04  mov ecx,[ebp+8]
  43bf07  mov ecx,[ecx+0x10]     ; 受击方 HP 上限
  43bf0a  cmp eax,ecx
  43bf0c  jbe 0x43bf11
  43bf0e  mov [ebp-4],ecx        ; 超出则夹到 HP 上限
  43bf11  mov eax,[ebp-4]
  43bf14  pop ecx                ; 平衡 0x43BF03 的 push eax
  43bf15  jmp 0x43bf19
  43bf17  xor ecx,ecx            ; ★第二个入口（另一条路径直接返回 0）
  43bf19  leave
  43bf1a  ret 0xC
  ```
- 改最终伤害就挂 **0x43BF11**（只能 6 字节，因为 0x43BF17 是另一入口）。洞穴里先照抄 `mov eax,[ebp-4]`+`pop ecx`，最后 `leave; ret 0xC`；`jbe 0x43BF11` 跳进来也落在同一点，安全。
#### 3.1.1 ★数据结构陷阱：参数是 0x24 战场对象，不是 0x48 单位记录

`0x43BC62` 的两个「单位」参数都是 **战场对象**（`0x4B2C50 + 序号×0x24`，见 `0x4061F9`），而特技/特效/装备查询那一套函数（`0x40BE7D`、`0x40BF10`、`0x43D4A0`、`0x4CF398`）要的是 **0x48 单位记录**（`[0x4CEA00] + 编号×0x48`）。两者互相喂错不会崩，但会算出垃圾索引、判断永远不成立 —— 这正是「补丁挂上去、伤害一点没变」的典型症状。

框架里现成的转换与现成的记录：

| 用途 | 取法 |
|---|---|
| 对象 → 记录 | `mov ecx, 对象; call 0x40658F` → ECX = 记录 |
| 记录 → 编号 | `push 记录; call 0x40BE7D; add esp,4` → EAX = 编号 |
| 对象 → 编号（一步） | `mov ecx,对象; call 0x40658F` 后按上行 |
| 对象 → 兵科行 | `mov ecx,对象; call 0x43B4A7` → EAX = 兵科行 |
| 对象 → 是否远程 | `mov ecx,对象; call 0x43FF9A` → AL = 0/1 |

而在 `0x43BF11` 这个出口上，**记录早就备好了**，不用再换算：

- `[ebp-0x24]` = 受击方记录（0x43BC88 存入，之后全程只读）
- `[ebp-8]` = 攻击方记录（0x43BC93 存入，之后全程只读）
- `[ebp-0x2c]` = 攻击方对象（入口 ECX）
- `[ebp+8]` = 受击方对象

⚠ 注意不要在洞穴里把 `[ebp-8]` 当临时变量用 —— 那是攻击方记录指针，覆盖掉就没法再判攻击方了。

### 3.2 策略伤害 0x43C00F（★真正的计算函数）

- 真正的策略伤害函数是 **0x43C00F**（`ret 0x10`；ECX=攻击方对象，[ebp+8]=受击方对象，[ebp+0xC]=附加记录，[ebp+0x10]=策略 id，[ebp+0x14]=0 实算 / 非 0 只估），返回最终伤害。
- 调用者 10 处：AI 评估 0x4231B7 / 0x423609 / 0x423FFE / 0x4240B5 / 0x4243FE / 0x425104；实际结算 0x438C9F / 0x43975E / 0x4406E3 / 0x44093F（0x438C9F 与物理 0x43BC62 是同一处分流）。
- **参数方向依据**：`0x5461F0`（被 0x43C2E3 调用，参数 `push [ebp-4]伤害 / push [ebp+8] / push [ebp-0x18]`）在 0x546204 先判 `byte[0x52CA0A]==1`（御风）则伤害置 0，再对 **[ebp+0xC] 对应单位**查 `byte[扩展行+0x3F]`（免疫标志）⇒ 0x43C00F 的 [ebp+8] 是受击方、[ebp-0x18]（=ECX）是攻击方。
- **0x40D200 只是其中一个子项**（`ret 8`，参数是攻击方/受击方两个对象，唯一调用者是 0x43C00F 的 0x43C0D4）：

```
40d206 push 0 / 2 / [ebp+0xC] / 2 / [ebp+8] ; call 0x40D2B0   → [ebp-4]=eax [ebp-8]=edx
40d21d push [ebp-4] / [ebp+0xC] / [ebp+8]   ; call 0x43D310
40d22e push [ebp-8] / [ebp+0xC] / [ebp+8]   ; call 0x43D3D0   → [ebp-8]=eax
40d255 mov eax,[ebp-4] / mov edx,[ebp-8] / ret 8
```

- `0x40D2B0` 返回 **EAX = 第二次计算的（攻击方侧）值、EDX = 第一次的（受击方侧）值**；两者都是 `0x43C3C1(对象, 2)` 再各乘自己的适性（`0x43F7B9(…, 0x1E)` / `(…, 0x20)`，经 `0x40C7C8 = 值×适性/10`）。若 [ebp+0x18]≠0 则跳过两次适性缩放。
- `0x43D3D0` 对 [ebp+8]（攻击方）查 **神机 78**，命中把精神力×25% 加到值上。
- ★**调用者只把 EAX/EDX 当「谁大谁小」的差值用**：0x43C110 `cmp [ebp-0x10](EDX=攻击方值), [ebp-0xc](EAX=受击方值)`；攻击方更大 → `damage += (EDX-EAX)/3`，否则 `damage -= (EDX-EAX)/3`（走 0x47FA9E）。
  ⇒ **只缩 EAX（受击方值）会把比较推向「攻击方更大」那支，伤害反而变大**——史进减伤 v5 实机就出现「策略伤害增加」。
- ★**策略侧的挂钩点应选 0x43C318**（`8B E5 5D C2 10 00` = `mov esp,ebp / pop ebp / ret 0x10`，正好 6 字节）：这里已是 **0x43C30D 夹紧上限之后**的最终值，而且 0x43C0C9（早期出口）正好跳到这里，换掉它不会漏。
  - 不要挂 0x43C315（`mov eax,[ebp-4]`）或 0x43C312：0x43C0C9 会跳进 0x43C318，挂前面会把那条出口踩成半条指令。
- 中间还有一串百分比修正：0x43C14A `imul [ebp-8]`（按 0x53E500+id 的百分比）、0x43C15D 兵科类型表 0x4D21B0、0x43C250 特效 0x28 加 / 0x43C274 特效 0x29 减、0x43C2A9 调 0x40CF10、0x43C2EC 调 0x5461F0（御风/免疫）。

### 3.3 装备特效查询链

- `0x4CF398` → `0x40BE7D`（单位指针→编号）→ `0x4D08DA` → `0x43C794`。
- `0x43C794(ret 0xC)`：`0x4079DA` 判有无该特效（0x64 默认百分比），要真实数值时 `0x407AF2`。
- `0x4079DA(ECX=单位,[ebp+8]=特效id)`：三个装备槽 `0x4065F0` → 物品 id（0xFF 空）→ `0x4837C2` → `0x40B4E1` → `0x43AD29` 得该装备的特效 id，比对命中返回 1。
- 常用特效 id：22 减轻远程损伤、23 减轻物理伤害、24 SP获取加倍、25 反击后反击、29 减轻法术伤害、34 节约MP、35 免疫远程攻击、44 二次行动、96 策略穿透范围、97 物理攻击范围、105 突破攻击。

### 3.4 兵科表与兵科类型

- 运行时行指针 `0x41B781` = `imul ecx,ecx,0x23; add ecx,0x4A7B0E`（80 行 × 35 字节）。exe 里 0x4A7B0E 全 0，运行时由 `0x41B740` 从 **Data.e5**（串 0x48BB60）用 `0x4CF6AE` 拷入。
- **Data.e5 偏移 0x9DB4 起，80 行 × 35 字节**：+0 = 移动力，+2..+6 = 五维成长档，+7 = 兵力档。**表中没有攻击范围列**。
- 兵科类型映射 `0x40BF10`：兵科 id ≤ 0x3B → type = id/3；0x3C..0x4F → type = id−0x28；≥0x50 → 0x28。
  ⇒ 弓兵 6/7/8→2，弓骑兵 12/13/14→4，弩兵 48/49/50→16，将军 54→18，器械 65→25，先锋 66→26，火器营 67→27，连环马 69→29，贵胄 70→30，咒术师 71→31，任侠 74→34。
  （已用 Data.e5 部队模板核对：战车/海鳅船/驼龙=65 器械，炮兵/巨炮车/风雷车=67 火器营，关胜/林冲等=54 将军，史进/晁盖=74 任侠，呼延灼/连环马=69 连环马。）

### 3.5 引擎自带的远程判定表 0x4D2138（★关键）

- **0x43FF9A(ECX=攻击方记录)**：先 0x43B4A7（记录→兵科行）→ `cmp al,0x27; ja → 返回 0` → `mov al,byte[eax+0x4D2138]`，返回 0/1。
- **0x4D2138 共 40 字节（按兵科行 0..39 索引）**，值为 1 的只有 7 类：

  | 兵科行 | 兵科 | 该兵科常见单位 |
  |---|---|---|
  | 2 | 弓兵 | 弓兵/高级弓兵/神射手 |
  | 4 | 弓骑兵 | 弓骑兵/连弩骑/游牧骑兵 |
  | 16 | 弩兵 | 连弩兵/高级弩兵 |
  | 18 | 将军 | 关胜/杨志/孙立/岳飞等 |
  | 27 | 火器营 | 炮兵/巨炮车/风雷车 |
  | 29 | 连环马 | 呼延灼/连环马 |
  | 34 | 任侠 | 史进/晁盖/邓飞等 |

- 消费点 `0x43BDDC`：`call 0x43FF9A` → 非 0 才用 `0x4CF398(受击方, …0x22)` 取百分比 → `damage = damage×百分比/100` → `0x42A959` 保证至少 1 点。**即：只有引擎认作「远程」的攻击，才会走受击方的远程减伤/免疫分支。**
- ⇒ 步兵、轻骑兵、枪兵、重骑兵等打人一律不吃远程减伤，实机观察（特效 22 对步兵/骑兵无效）与此完全一致。
- ⚠ 0x43BDEE 处查询的代码 id 是 `0x22`，而名表 0x5265C0 的 34 号却是「节约MP」⇒ 名表下标与代码 id 之间还隔着一层 `[0x500C3B]+id*8` 的重映射表（`0x4D08DA` 返回该表 +7 字节的值），**不能只按名表下标推断行为**。`0x43BE5C` 的 0x23(35 免疫远程攻击) 与名表一致。


## 4. 实现·使用方法

按「远程」区分伤害时，**直接读引擎自己的表**，不要自己维护白名单：

```asm
mov ecx, <攻击方单位记录>
call 0x40BF10              ; ECX=记录 → EAX=兵科行(0..39)，ECX 保持
movzx eax, byte [eax+0x4D2138]
test eax, eax              ; 0=近战, 1=远程
```

这样与引擎的特效 22/35 口径完全一致（含 将军/任侠/连环马 这三类非常见的「远程」兵科）。案例见 [史进减伤](../10-制作案例/史进减伤.md)。

改 `0x5265C0 + id×16` 只动名字字面量、不改行为；要改行为必须改消费该 id 的代码点。

## 5. 风险与边界

- 0x43BF11 只能改 6 字节（0x43BF17 是第二入口）。
- 0x43BC62 有 5 个调用点，挂在出口 0x43BF11 才能全覆盖（只挂 0x5B0812 会漏必杀/反击的路径）。
- 策略侧的真正出口是 0x43C00F 尾部 **0x43C318**（不是 0x40D255）；`0x40D200` 只是它内部的一个子项，改那里的中间值会让「攻防差值」分支反向、伤害反增（史进减伤 v5 实测）。补给类策略若也走 0x43C00F，减伤会同时减少治疗量（未验证）。
- 「远程」按**兵科**判定而非距离 ⇒ 弓兵贴脸打也算远程；将军/任侠/连环马这类近战外观的兵科也被引擎记为远程（它们在本作应有 2 格攻击）。
