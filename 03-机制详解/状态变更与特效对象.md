# 状态变更与特效对象

## 结论速览

- 状态特效不是「一次性播个动画」，而是一个**长生命周期对象** `0x4917B0`：内部有最多 116 个槽（`0x74`），每个槽有出生位置、绘制位置、出生时刻。
- 关键契约：`0x40196F(obj, count, 数组, flag)` 是「**一次提交一整张列表**」；连续多次 `count=1` 调用会把图标沿时间轴排成依次出生，而不是同时出现。
- 这就是「区域状变 v1 图标错位」的根因，也是 v2 改用引擎自带收集通道后能对齐的原因。
- 驱动函数 `0x45AE08` 自带「把命中单位号收集进 byte 数组」的通道，只是原调用点传了 `eax=0` 从没用。

## 适用版本

- 6.1 魔改（罡星 112/117 关）。

## 已确认事实

**特效对象 `0x4917B0`**

| 偏移 | 含义 |
|---|---|
| `+0x00` | byte 元素数（一个元素 = 一帧动画） |
| `+0x08`/`+0x0C` | 图标宽/高（用于 `w/2, h/2` 居中） |
| `+0x10`/`+0x14` | 元素指针数组（上一元素 / 当前元素） |
| `+0x294` | 元素构建锁（非 0 时 `0x401000` 直接返回 0） |
| `+0x298` | sprite 句柄 |
| `+0x29C` | 时间基准常量 `0xB3100` |
| `+0x2A0` | 出生计时累加器 |
| `+0x2A4` | byte 已用槽数（上限 `0x74`） |
| `+0x31C` | 槽数组：每槽 8B `{x,y}` 出生位置 |
| `+0x6BC` | 槽数组：每槽 8B `{x,y}` 绘制位置（初始 `-1000`） |
| `+0xA5C` | 槽数组：每槽 4B 激活标志 |
| `+0xC2C` | 槽数组：每槽 4B 出生时刻 |
| `+0xB4` | 帧表 |
| `+0xFD0` | 播放结束时刻 |

**关键函数**

| 函数 | 语义 |
|---|---|
| `0x40BCF6(this, 图标号)` | 准备一个特效对象：`0x4016CD` 复位 → 载 sprite → 建帧表 → 设 `+0xFD0` → `[+0x2A0] += 宽*高*0x415B10()` |
| `0x4016CD(this)` | 全清：`+0x298/+0x29C/+0x2A0/+0x2A4` 与三个槽数组 memset |
| `0x401000(this, src)` | 元素（动画帧）构建：`[+0x294]=0x14`，每帧 `0x14` 字节，帧自带 `+8/+0xC` 小偏移 |
| `0x452F9D(this, unitIdx)` | `0x40196F(this, 1, &unitIdx, 0)` 的薄封装，`ret 4` |
| `0x40196F(this, count, ptr, flag)` | **一次提交整表**；`flag=0` 读 byte 数组、`1` 读 WORD；自带 `0x74` 上限裁剪；`ret 0xC` |
| `0x401A7E(this, count, posArray)` | `0x40196F` 的内核：算 delay、分配槽号、写出生位置/出生时刻 |
| `0x401E5D(this, arg0, arg1)` | **阻塞播放**：外层按元素、内层按槽，逐帧绘制 |
| `0x40179A(this)` | 按 (Y,X) 对槽位做插入排序（只交换位置，不动出生时刻/激活标志） |
| `0x40186F(this)` | 逐槽遮挡判定 |
| `0x40208B(this, elemIdx, flag)` | 算 sprite 区域并 blit；随后把绘制位重算为「出生位 + 帧偏移」 |
| `0x402396(this, elemIdx, slotIdx)` | 真正画一片；按 `0x415B10()` 分两条路径 |
| `0x4013B5(this, delay)` | 延后队列（放不下的项挂到这里） |
| `0x415B10` | 读配置字节 `byte[[0x4BD044]+0x4066C8]`（返回 0/1，决定绘制路径） |

**`0x401A7E` 的真实契约**

```
上限检查：eax = byte[obj+0x2A4] + count；cmp 0x74; jbe → 否则 count = 0x74 - 已有（可变负 ⇒ 静默丢弃）
delay = [obj+8] * [obj+0xC] * 0x415B10()
循环1 每项：
   if [obj+0x2A0] + delay >= [obj+0x29C] → 跳循环2
   槽号 = 0x2A4 + i
   出生位 = pos - (w/2, h/2)
   绘制位 = 0xFFFFFC18 (-1000)
   出生时刻 = [obj+0x298] + [obj+0x2A0]
   [obj+0x2A0] += delay
循环2：余项调 0x4013B5(this, delay)，返回 0 就 break（连坐标都不写）
尾：add byte[obj+0x2A4], al（al=实际放下的条数）
```

**驱动 `0x45AE08`（区域状态变更）**

- 入口：`[ebp-0x20]`=特效对象、`[ebp-0x24]`=**调用方给的单位号收集数组（可为 0）**、`[ebp-0x30]`=已写条数。
- 双层 `(x,y)` 扫描 `0x435884` 取地面单位 → `0x4061F9` 取记录 → `0x418C90` 判阵营 → `0x43FC1A` 决定状态标志。
- 收集通道（关键）：
  ```asm
  0x45AEFE mov eax,[ebp-0x24]
          cmp eax,0
          je  0x45AF13
  0x45AF06 mov ecx,[ebp-4]        ; 单位号
  0x45AF09 movzx edx,byte[ebp-0x30]
  0x45AF0D mov byte[eax+edx],cl
  0x45AF10 inc byte[ebp-0x30]
  ```
- 原调用点 `0x415428`：`mov ecx,0x4B5DF0; xor eax,eax; call 0x45AE08` ⇒ **一直传 0，收集通道从没用过**。
- 11 个调用点中，唯一自带数组的是 `0x450EE3`（写进 `0x497B05`）。

## 实现/使用方法

**正确的批处理写法**

1. 在调用点传一个洞穴里的缓冲区（容量 ≥ `0x74`），让 `0x45AE08` 自己收集单位号。
2. 循环结束后**只调一次** `0x40196F(obj, 条数, buf, 0)`。
3. 再调一次 `0x401E5D(obj, 0, 1)` 播放。
4. 最后 `0x4016CD(obj)` 复位。

**错误写法（会错位）**

- 在循环里对每个单位调 `0x40BCF6 + 0x452F9D + 0x401E5D + 0x4016CD`：速度对了，但每次都复位 ⇒ 清单永远 1 条；而若为了批量而省掉复位，逐次 `count=1` 会让 `[+0x2A0]` 累加 delay，图标被排到未来。

## 风险与边界

- `+0x74` 上限是硬裁剪，超过的项会被静默丢弃（不报错）。
- `+0x2A0` 与 `+0x29C` 的关系决定「哪些项进延后队列」；复位不彻底会累积。
- 同一对象被多处同时使用时，最后调用的会覆盖前面的列表。
