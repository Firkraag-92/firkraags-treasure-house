# 05 · 教程指南

> 从「想改一个功能」到「交付一个可实机验证的产物」的最小闭环。

## 这一层讲什么

流程固定七步：读现状 → 定位锚点 → 写脚本（带断言）→ 静态复核 → 本地冒烟 → 实机验证 → 写日志。

其中静态复核与实机验证不可省：冒烟只能证明不崩，不能证明改对了。

## 阅读顺序

- 照着顺序做一遍，把每步的产物（脚本、diff、日志）留下来，下次重做才有据可依。
