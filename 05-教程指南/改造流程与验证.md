# 改造流程与验证

## 结论速览

- 一个改动从想法到交付的最小闭环：**读现状 → 定位锚点 → 写脚本（带断言）→ 静态复核 → 本地冒烟 → 实机验证 → 写日志**。
- 其中「静态复核」与「实机验证」不可省；冒烟只能证明不崩。
- 每个产物必须是**独立文件名**，不覆盖用户的现役 exe。

## 适用版本

- 6.1 魔改 exe 的一切改动。

## 已确认事实

- 用户要求：每次修改后出 txt 日志（时间、对象、md5、改了哪里、验证状态）。
- 用户要求：需要他实测时**当轮停下来一次说清步骤**，不要挤牙膏。
- 用户不接受「为了改而改」：功能入口不得破坏原有布局。

## 实现/使用方法

**第 0 步：确认基底**

```powershell
Get-FileHash -Algorithm MD5 <exe>
```
对照 [版本与基底](../00-总览与规范/版本与基底.md)，md5 不对就停下来查是哪一份。

**第 1 步：定位锚点**

优先级从高到低：
1. 用户看得见的锚（控件号、格式串、名表指针）→ 反向找引用点。
2. 已知机制页里的函数地址。
3. 字节级扫描（`E8/E9 rel32`、`ff 14 85` 索引表、立即数）。

**第 2 步：写脚本（必须带断言）**

```python
BASE = "6bd4c3ea68e7ad372a581718087ff36d"
assert md5(data) == BASE
assert data[hook:hook+5] == b"\xE8\xEB\x63\x00\x00"
assert data[cave:cave+size] == b"\x00"*size
# ... 打补丁 ...
assert len(data) == 7413760
```

**第 3 步：静态复核**

- capstone 反汇编洞穴，逐条对照设计。
- 统计 diff：字节数 + 命中区间，确认没有溢出。
- 检查挂钩点附近有没有跳转落入被改写区。

**第 4 步：本地冒烟**

```powershell
Start-Process -FilePath <exe> -RedirectStandardOutput out.txt -RedirectStandardError err.txt
Start-Sleep -Seconds 5
```
> 不加重定向会把工具调用拖到超时（子进程继承 stdout 管道）。

**第 5 步：实机验证**

写清楚：进哪个界面、做什么操作、期望看到什么、失败了看什么。

**第 6 步：写日志**

追加到 `112关工作目录\_exe分析\修改日志.txt`，格式见 [修改日志规范](../06-项目与工具链/修改日志规范.md)。

## 风险与边界

- 冒烟通过 ≠ 功能正确；用户实测前不要把结论写成「已完成」。
- 挂钩用 `jmp` 时要自己 `push` 返回地址，否则现象是「随机闪退」，很难定位。
- 洞穴被多个补丁共用时会互相覆盖；合并前先列占用表。

## 证据来源

- 本会话多次实战（区域状变 v1/v2、列传 v1 闪退、清 SP 六版失败）
- 证据等级：已验证。
