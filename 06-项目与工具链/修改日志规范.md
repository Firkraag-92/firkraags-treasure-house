# 修改日志规范

## 结论速览

- 用户要求：**每次修改后出一份 txt 日志**，介绍本次改动时间与内容。
- 位置：`112关工作目录\_exe分析\修改日志.txt`（UTF-8 带 BOM，**追加式**）。
- 每条至少包含：时间、标题、对象（基底→产物 + md5）、改了哪里、验证状态。

## 适用版本

- 6.1 魔改项目全部改动。

## 已确认事实

- 日志已从 2026-10-17 记到 2026-10-21（约 21 KB）。
- 大文件写入铁律：`read` 工具默认 2000 行 / ~54 KB 上限，超过会静默截断；**只能用 `Add-Content` 追加或 `edit` 锚定尾部唯一串**，不能用 read+write 整文件重写（曾把 2522 行的文档写成 310 行）。

## 实现/使用方法

**单条格式**

```
[2026-10-20 18:52] 标题
  对象: <基底文件名> (md5 <旧>) -> <产物文件名> (md5 <新>)
  改动: <挂钩点/洞穴/数据文件，逐条列出>
  验证: <未测 / 实机通过（用户原话）/ 失败现象>
```

**追加方式（PowerShell）**

```powershell
$txt = @"
[2026-10-21 10:00] 标题
  对象: ...
"@
$txt | Out-File -FilePath "112关工作目录\_exe分析\修改日志.txt" -Append -Encoding utf8
```

**同时更新**

- 用户面向的 `更新日志_整合5项_v1.txt`（`117关工作目录\` 与 `_dev\罡星_dev3\` 各一份）。
- 但用户明确交代过的条目（如「列传导入」那段）**不要写进更新日志**。

## 风险与边界

- 不要用 `Get-Content | Measure-Object -Line` 判断行数（编码不同会给出错误数字）。
- 修改日志里不要贴完整反汇编，只贴关键几条 + 偏移。
