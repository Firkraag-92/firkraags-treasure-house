## 实现/使用方法

**找调用者的正确姿势**

```python
# 字节级扫 E8/E9 rel32，最可靠
target = 0x4784C7
for i in range(len(data)-5):
    if data[i] in (0xE8, 0xE9):
        rel = int.from_bytes(data[i+1:i+5], "little", signed=True)
        if (i + 5 + rel) == target: ...
```
线性反汇编（`md.disasm`）在 117 基座上会因对齐噪声漏掉大量调用者。

## 重建（搬运式）——换基底时怎么复用

现役改动全部可以用「从现役 exe 整段搬代码块 + 重打 15 个挂钩字节」重建，不需要重新汇编。

- 详细清单（15 处挂钩的原字节/新字节、20 个代码块范围、6 处数据改动、重建顺序、校验清单、失败台账）见：`117关工作目录\_exe分析\维护日志_重做指南.md`。
- 搬运脚本骨架：

```python
src = open(DONOR, 'rb').read()               # 现役 exe
dst = bytearray(open(NEWBASE, 'rb').read())  # 新基底
for lo, ln in BLOCKS:                        # VA 起 + 长度
    a, b = va2off(src, lo), va2off(dst, lo)
    assert not any(dst[b:b+ln]), '目标区不是空的'
    dst[b:b+ln] = src[a:a+ln]
```

- 前提：新基底与 117 基底同构（同段表、同锚点字节）。不同构时先跑 `diff_exe_new.py` + `probe_new_base.py` 核对锚点后再决定。
- 运行期 BSS 不用搬（文件里本来就是 0）：`0x629000` 地形缓存（0x100×0xC）、`0x634200` 批量缓冲、`0x634300` MODE、`0x634304` PTR。
- 挂钩之外还有两处「非 jmp」改动别漏：`0x452321` 是 call 的**操作数**改写（保留 E8），`0x40BFE9` 是 `cmp eax,0x400` 立即数的**第 2 字节**。

## 风险与边界

- `sweep2.pkl` 只覆盖 `.text`；`.data2`/`.data3` 的引用必须全文件字节扫描。
- `dis_any.py` 对某些地址静默无输出，不要据此判断「函数不存在」。
- keystone：asm 源不能有 `;` 注释；不能拼接分别汇编的片段。
