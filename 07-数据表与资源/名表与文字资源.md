# 名表与文字资源

## 结论速览

- 技能名表在 `0x4F0BA0`（指针数组，0..0x7E），字符串本体在 `0x4F15E0` 附近，每串 16 字节定长槽。
- 界面文字大量是「运行时拼串」：`【` + 名字 + `】`，**不存在独立的「【我军】」字符串**。
- 兵科名表在 exe 文件 `0x8B010`（9 B × 40），地形名串在 `0x8AE70`。
- 改文字有两种安全做法：改名表指针指向新串；或在 `Imsg.e5` 追加记录。

## 适用版本

- 6.1 魔改（罡星 112/117 关）。

## 已确认事实

**技能名表 `0x4F0BA0`**

- 结构：`dword 指针[0x7F]`，下标 = 技能编号。
- 槽 0 = 【无】；1..30 招式；31..48 秘术；49..63 合技；64..107 特技/异术混排；108 = 占位串「【」（表内最后一项），**109 起指针错位成垃圾**。
- 字符串本体：`0x4F15E0` 一带，每串 16 字节槽，GBK 编码。
- 名表项地址 = 表基 + 编号×4；文件名偏移 = `VA - 0x42E800`（名表本身在 `.data2`）。

**界面文字的拼装**

- `【我军】`/`【敌军】`/`【友军】`/`【中立】` 全文件 0 命中；`我军`/`敌军`/`友军` 是大串里的子串且无 dword 指针引用 ⇒ 界面拼「【」+名字+「】」。
- 情报窗控件号：招式 `0x5AB`、秘术 `0x5AC`、合技 `0x5AD`、特技&异术 `0x5AA`、列传 `0x5A6`、说明 `0x804`。
- 回合显示格式串 `0x500C5F` =「回合数 %d/%d」，控件 `0x433`。

**名字覆盖表 `0x510D00`**

- 48 项 × 16 字节：`word 编号` + 名字槽；文件初值每项首 word 都是 `0x400`。
- 写入端 `0x4081F2`（72/0 改名）；读取端 `0x404365`、`0x44F03B`（文字绘制例程）。
- 名字是**内存覆盖**：换关重载就复原 ⇒ 每关都要重新设置。

**Data.e5 的名字**

- 人物表 `0x18C + 索引*0x20`，8 字节 GBK。
- ⚠ 按**表索引**取名字，不是按 `+0x0D` 的编号。

## 实现/使用方法

**改一个技能名**

1. 把新串写到 `.data3` 的零区（GBK + `00`）。
2. 把名表对应项的 dword 改成新串 VA。
3. 注意：名表项在 `.data2`，修改是等长 dword 替换，不动文件结构。

**加一条新技能名（不占用现有编号）**

占用表中的占位项（如 108）→ 改成新串指针。但 108 已被「张顺天运」用过，做新功能前先查现表。

**改界面固定文案**

找到格式串地址（如 `0x500C5F`），等长替换其中的字；改长会破坏相邻串。

## 风险与边界

- 名表指针区间只到 108；越界读会拿到垃圾。
- `0x47FC7D` 的 strcpy 无长度检查，名字超过约 14 字节会串写到下一项。
- 文字分「显示名」与「逻辑名」，改名只影响显示，某些逻辑仍按原来比字符串（例如列传匹配）。
