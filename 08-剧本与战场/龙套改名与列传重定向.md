# 龙套改名与列传重定向

## 结论速览

- 罡星只有 1024 个武将位，工程里把一部分当「龙套槽」反复复用：每关用 `72 0` 把它们改成需要出场的角色。
- 改名是**内存覆盖**（表 `0x510D00`），换关重载就复原 ⇒ 每关都要重设。
- 列传原本「一人一份」，用 `Imsg.e5` 记录 `0x39A + 编号`；为了给龙套不同的列传，我们加了「名字 → 列传号」的覆盖层（洞穴 `0x639000`）。
- 现役方案（117 关）：挂钩 `0x4784C7`，先看扩展行字段 14，再按「单位记录 `+8` 名字」与 `0x510D00` 覆盖表里的新名字匹配，命中就把列传号换成表里的记录号。

## 适用版本

- 6.1 魔改（罡星 117 关）。

## 已确认事实

**改名机制**

- `72:信息传送 0` 的处理器 = `0x4081F2`（`ret 4`）：
  ```
  edx = [0x505F58]              ; 变量 4054 的值（低 16 位 = 编号）
  if dx >= 0x400 → 退出
  ecx = 0x4061E4(edx)           ; 单位记录
  ecx += 8
  0x4D0C20(文本, 1, ecx)        ; 读名字写到记录 +8
  循环 0..0x30: 在 0x510D00 里找 同编号 或 空项(0x400) → 写入 word 编号 + strcpy 名字
  ```
- 覆盖表 `0x510D00`：48 项 × 16 B（word 编号 + 名字槽），文件初值每项首 word = `0x400`。
- 读取端 `0x404365`、`0x44F03B`（文字绘制）。

**复用现状（全量扫描 848 条改名）**

- 分布在 114 个 S 剧本里的 106 个；编号 0..1023。
- 分类：高级XX **765 条**；其它龙套 57；有名角色槽 26。
- 只用了 **20 个高级龙套槽**；最热：174（79 次）、157（73）、149（64）、147（59）、148（57）、178（50）、150（43）、193（38）。
- 名字最长 5 汉字，无超过 7 汉字（与 `0x510D00` 的名字槽容量相符）。
- 第 4 关样例：S004:47 槽 147 → 张三11；53 槽 148 → 李四11；59 槽 149 → 富吉11；65 槽 150 → 薛宝11；71 槽 124 金翠莲 → 乌鸦11；379 槽 147 → 孙高11。

**列传链路**

- 情报窗 `0x4783C1` → `0x482715` 取编号 → `0x40BFDB(buf, id)` → 记录 `id + 0x39A`。
- 现役覆盖层（`0x639000`）：
  ```
  esi = 编号
  守卫：编号 < 0x400、[0x4CEA00] != 0
  候选名1 = [0x4CEA00] + esi*0x48 + 8
  call scan（表在 0x636000，count + 493 条 × 20B）
  失败 → 扫 0x510D00（48 项）找同编号，用其名字再 scan
  命中 → 把 0x40BFDB 的 id 参数换成记录号
  尾部：push 0x4784CC; jmp 0x40BFDB
  ```
- 表项格式（20 B）：名字 14 B（GBK+补 0）+ slot word + record word + pad。
- 匹配规则：表项名字是运行名前缀，运行名其后须为 `0` 或 `0-9`（吃掉脚本里写的尾数字，如「张三11」→「张三」）。

## 实现/使用方法

**给新龙套配列传**

1. 在 `Imsg.e5` 末尾追加 200 字节记录，记下记录号（`len//200`）。
2. 在覆盖表里加一条：名字 + slot + record。
3. 剧本里照常 `72` 改名。
4. 进游戏看情报窗。

**同名不同人**

- 靠 slot 区分（slot = `0xFFFF` 表示通配）。
- 同名且同 slot 的两关无法区分（范全关 87/关 99 都是 204 槽，只能显示关 87 版）。

## 风险与边界

- 名字覆盖是内存态，读档后要重设；列传覆盖表是静态的，不依赖剧本。
- 表项名字若超 14 字节会破坏相邻项。
- 改名依赖「该单位已加入我军」（编辑器会自动补提示）。
