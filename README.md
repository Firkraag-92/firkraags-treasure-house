> 一套围绕《三国志曹操传》6.1 魔改引擎（罡星煞曜传内核，`Ekd500.exe` / `Ekd5.exe`）的逆向笔记与 MOD 改造手册：地址口径、数据结构、挂钩纪律、已交付案例与失败台账。

**适合谁**：给这支引擎写补丁、移植 MOD 的人；正在反汇编这支 exe、需要地址与调用约定的人；接手罡星煞曜传工程、先要弄清红线的人。

**不适合谁**：想找成品修改器的人（本库只有知识、不含工具与游戏文件）；想跨引擎直接搬地址的人（见 [6.1 与其他引擎的差异](09-版本与外部资料/6.1与其他引擎的差异.md)）。

**读法**：只想查东西 → 直接看下面的「快速导航」；第一次接触 → 先读 [引擎结构总览](01-核心引擎/引擎结构总览.md) 再做 [改造流程与验证](05-教程指南/改造流程与验证.md)；想抄现成改法 → 进 [10-制作案例](10-制作案例/)。

## 结论速览

- 本目录是「6.1 魔改引擎」这一支 exe 的唯一主知识库：逆向结论、地址口径、数据结构、修改案例与失败台账都在这里。
- 默认服务对象：`Ekd500.exe` / `Ekd5.exe`（7,413,760 B、PE32 x86、ImageBase `0x400000`、9 段）。所有地址默认以「干净基底」为准，换 exe 必须重新核对锚点字节。
- 引擎血统：这一支是**小白狐**在 KOEI 底座上的 6.1 魔改，**不继承** star175 6.6、也不继承普罗 6.5PL。三者只共享基座，72 指令下标体系、扩展行布局都是小白狐自己的约定。
- 修改红线（用户明确要求）：不改文件长度、不改段表/入口/导入表、不改数据表本体；只做「最小字节挂钩 + 往 `.data3` 全零区放代码」；数据文件只在末尾追加。
- 所有结论都标了证据等级。没做实机验证的，一律不许写成可写回规则。

## 适用版本

- 默认适用：6.1 魔改（罡星煞曜传）的 `Ekd500.exe`（112 关版）与 `Ekd5.exe`（117 关版）。两者**段表、关键函数地址逐字节一致**，可直接互用地址表。
- 6.5PL（普罗）、6.6（star175）、瓦岗（star175 系二次改造）只能作为**对照**，不能把它们的地址搬过来。差异见 [6.1与其他引擎的差异](09-版本与外部资料/6.1与其他引擎的差异.md)。
- 新拿到的 6.1 基底如果只是「换了几十到几千字节」的同构版本，先按 [版本与基底](00-总览与规范/版本与基底.md) 的锚点表核对，再决定能不能复用。

## 已确认事实

- 单位记录 = `[0x4CEA00] + 编号 × 0x48`，名册上限 1024；战场对象 = `0x4B2C50 + 序号 × 0x24`，同场上限 256。
- 扩展行 = `0x5E0000 + 编号 × 0x40`，由剧本 `72 16` 写入，随存档走。
- 剧本 `72` 指令的子功能表在两支引擎里**基址不同**：6.1 是 `0x47D903`，6.5PL 是 `0x47D8DF`。
- `.data3`（VA `0x626000` 起、file `0x1F7800` 起、5 MB）大段全零，是唯一的代码洞来源；洞穴选址必须现场断言全零。
- 挂钩纪律（踩过两次闪退）：把 `call` 改成 `jmp` 后，补丁交还原例程前必须自己 `push` 返回地址，并且栈参数整体偏移 4 字节。

## 实现/使用方法

1. **要改一支 exe**：先读 [改造流程与验证](05-教程指南/改造流程与验证.md)，按「基线冻结 → 锚点核对 → 洞穴选址 → 字节断言 → 汇编 → 挂钩 → 反汇编复核 → 冒烟 → 实机 → 日志」走。
2. **要查某个机制**：先看 [引擎结构总览](01-核心引擎/引擎结构总览.md)，再进 `03-机制详解` 对应页。
3. **要查某个函数**：直接查 [函数速查表](04-函数速查/函数速查表.md)。
4. **要照抄一个已成功的改法**：进 `10-制作案例`，每个案例都写了挂钩字节、洞穴布局、产物 md5、实测结论。
5. **改完必须写日志**：格式见 [修改日志规范](06-项目与工具链/修改日志规范.md)。

## 风险与边界

- 地址只在「同一次编译」内有效。换基底先用锚点表验证；不同则整套地址作废。
- `.data3` 段属性可写可执行是**节级**标志，个别页运行时不可执行（`0x629000` 页实测执行即崩），洞穴要避开并实测。
- 同一片洞穴可能被多个补丁占用（`0x630000` 同时是张顺天运与清 SP 的洞穴）。合并补丁前先看占用表。
- 剧本 `.eex` 用 `eexlib` 改长度后自校验能过，但**用户的剧本编辑器不认**、游戏会崩（未解）。正式剧本改动前必须三方复核。
- 情报窗说明文本、SP 跨关清空、1024→2048 扩容这三件事仍是未闭环状态，见 [待验证清单](00-总览与规范/待验证清单.md)。

## 证据来源

- 本地逆向记录：`112关工作目录\_exe分析\`（原文索引见 [原文索引](90-来源归档/原文索引.md)）。
- 补丁脚本与产物：`脚本目录\`、`工程工作目录\_dev\罡星_dev2`、`罡星_dev3`、`117关工作目录\`。
- 证据等级：本库条目默认「已验证（本地反汇编 + 实机）」；仅静态推断的会写明「待证」。

## 待验证项

- 每关清空敌军 SP 的可靠落点（现有 6 个版本全部无效，见案例复盘）。
- 张顺专属天运的情报窗说明文本仍是原版。
- `0x41CF0C`/回合数写入 `0x41D005` 这一套旧战斗流程实战中命中数为 0 —— 真正的开战路径仍在 `.data2` 未定位。
- 瓦岗「怒目」这类特技的效果执行代码不在 id 数组的读者里，尚未定位。
- 单位记录（0x48 字节）里 MP 字段偏移未确认。
